# Internationalization (i18n)

English is the default language (LTR). Hebrew is a first-class citizen (RTL). Everything customer-facing is bilingual: the site, the create flow, the emails, and the game itself.

## How it works

| Layer            | Mechanism                                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| Site language    | Cookie `findme_locale` (`en` \| `he`), set by the globe button (`LanguageSwitcher`). Default: `en`.   |
| Dictionaries     | `src/i18n/dictionaries/en.ts` is the source of truth; `he.ts` is typed as `Dictionary` (= `typeof en`) so a missing key fails typecheck. |
| Server pages     | `const { locale, t } = await getI18n()` (`src/i18n/server.ts`).                                        |
| Client comps     | `const { t, tf, locale, dir } = useI18n()` (`src/i18n/client.tsx`). Provided once in the root layout. |
| Placeholders     | `tf(t.some.key, { name })` fills `{name}`.                                                             |
| Errors           | Services return `{ ok: false, code, reason }` (`src/i18n/errors.ts`); UI renders `errorText(t, err)`.  |
| Prices           | `formatPrice(agorot, locale)` → `₪19.90` / `19.90 ₪`. Prices stay in ILS for now.                      |
| Scenes           | Every copy field in `scene.json` is `{ "en": "…", "he": "…" }` (`LocalizedText`).                       |
| Game             | `Game.locale` is frozen at draft creation from the parent's site language. `composeGameConfig` picks that language, so a play link behaves the same for everyone who opens it. The renderer reads `config.locale` (`src/game/i18n.tsx`) and sets `dir` on the game root. |
| Emails           | `magicLinkEmail` / `gameReadyEmail` take `locale` (the user's / the game's).                            |
| Admin            | Internal tool, Hebrew only (uses `.he` fields directly).                                               |

## Adding a string

1. Add it to `en.ts` (English copy).
2. Typecheck fails until you add it to `he.ts`.
3. Use `t.path.to.key` (server) or `useI18n().t` (client).

Never hardcode customer-facing text in components. Gendered Hebrew is avoided by design ("מצאו את {name}", the child speaks in first person).
