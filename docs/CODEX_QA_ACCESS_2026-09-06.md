# שער סיסמה ל־QA — מסירה לבודק שני

## מטרה וגבולות

בקשת המשתמש: לא לאפשר למי שמגיע במקרה ל־QA להפעיל יצירת משחק במימון הפרויקט. השינוי נוגע ל־QA בלבד; אתר הפרודקשן נשאר paused ב־Vercel. לא השתנו רשימת הבודקים, מכסת ההוצאה, התשלום המדומה, איכות הרנדר או התנהגות המשחק.

הגנת הסיסמה המובנית של Vercel דורשת בחשבון הנוכחי תוסף Advanced Deployment Protection של $150 לחודש. **לא הופעל תוסף ולא נרכש דבר.** מקור: [Vercel Deployment Protection](https://vercel.com/docs/deployment-protection).

## שתי שכבות

1. **כתובות פריסה ישנות/Preview:** הופעלה Vercel Authentication ברמת Standard Protection בפרויקט `find-me-qa` בלבד. `ssoProtection.deploymentType = prod_deployment_urls_and_all_previews`. כתובות אלה דורשות הרשאת Vercel, כולל פריסות היסטוריות שאין בהן את הקוד החדש. השינוי אינו מגן בעצמו על הדומיינים הראשיים של פרויקט QA.
2. **דומייני QA הנוכחיים:** שער סיסמה בצד השרת. Middleware מכסה דפים, דמו, תמונות, API ו־Server Actions. בנוסף, כל Route Handler קיים וכל Server Action של יצירה/ספרייה/אדמין/שפה בודקים הרשאה בעצמם, לפני פעילות עסקית. בדיקות קוראות ישירות למסלולים בלי middleware ומוודאות שלא מגיעים אפילו לקונטיינר.

`QA_TESTER_EMAILS` והגבלת הוצאה נשארים בעינם — הסיסמה אינה הרשאת אדמין, אינה מוכיחה בעלות על משחק ואינה עוקפת את הרשאות המשתמש הקיימות.

## סודות וכניסה

- משתנה **Secret** בשם `QA_ACCESS_PASSWORD` בפרויקט `find-me-qa`, בסביבת **Production של פרויקט QA**. המשתמש מזין ישירות ב־Vercel; אין ערך בקוד, בקובץ התיעוד או בדוח.
- 16–256 תווים, סיסמה ייחודית וחזקה. ערך חסר/קצר/ארוך מדי או מפתח חתימה חסר משאיר את האתר סגור (503), לא מדלג על השער.
- השער פעיל אוטומטית כש־`APP_ENV=qa`. אין דגל opt-out. ב־development וב־production התנהגות האתר הקיימת נשמרת.
- עוגייה חתומה ב־HMAC-SHA256, עם nonce ותפוגה של 24 שעות. `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, קידומת `__Host-`, ללא `Domain`. אינה מכילה סיסמה או hash שלה. הרשאה שנשמרה בדומיין הישן אינה עוברת לדומיין החדש.
- החלפת סיסמת QA או `SESSION_SECRET` **ופריסה מחדש** מבטלות עוגיות ישנות בפריסה החדשה. פריסות היסטוריות נשארות מאחורי Vercel Authentication.
- השוואת סיסמאות וחתימות ב־Web Crypto; אין השוואת מחרוזת מוקדמת של סיסמאות. הסיסמה אינה מועברת ל־Client Component, ל־URL או ללוג.
- התחברות עובדת בטופס HTML בלי JavaScript. נבדק Origin זהה; `next` יכול להיות רק נתיב מקומי בטוח. קישור למייל/משחק נשמר דרך ההתחברות.
- הגבלת ניסיונות: 10 לכל IP ב־15 דקות **לכל תהליך**. זו הקשחה בסיסית, לא מגבלה גלובלית על כל instances ב־serverless. לכן נדרשת סיסמה חזקה; לפני פתיחה לקהל/צוות רחב לשקול WAF או limiter מבוזר.
- תגובות השער אינן נשמרות ב־cache. QA מקבל `X-Robots-Tag: noindex, nofollow, noarchive` ומטא־דאטה תואמים. `noindex` אינו תחליף לסיסמה.

## Cron וחריגים

- רק `GET/POST /api/jobs/tick` **ללא query** יכול לעבור עם `Authorization: Bearer <CRON_SECRET>` תקין.
- אותו מפתח אינו מאפשר `/create`, `/api/dev/mock-pay`, webhook או tick עם `gameId`.
- התשאול מדף ההמתנה משתמש בעוגיית QA ובבדיקת הבעלות הקיימת.
- `/api/health` חסום גם הוא ב־QA. בדיקה חוזרת דורשת עוגיית כניסה; `vercel curl` עוקף רק הגנת Vercel, לא את שער האפליקציה.
- רק עמוד הכניסה, POST ההתחברות וקובצי `_next/static` לקריאה זמינים לפני כניסה. POST לכתובת static אינו פטור.
- webhook התשלום אינו פטור ב־QA: התשלום כאן מדומה, ובעל המשחק מפעיל את מסלול mock-pay מתוך כניסה. פרודקשן לא משתנה. אם QA יעבור בעתיד לספק תשלום אמיתי, יש לתכנן חריג חתום מצומצם, לא לפטור את כל `/api`.

## אירוע פלט האבחון

בקריאת הגדרות הפרויקט הודפס בטעות טוקן ה־Vercel automation bypass הקודם. הוא הוחלף מיד דרך Regenerate Secret. אומת שנשאר טוקן אחד עם זמן יצירה חדש. הטוקן החדש לא הודפס ולא נשמר בדוח; ערכי OpenAI/DB/Resend וסיסמת QA לא נקראו. אוטומציה שמחזיקה עותק ידני ישן תצטרך לקבל את החדש בערוץ סודי; בפריסה חדשה Vercel מזריק את System Environment Variable המעודכן.

## בדיקות לקלוד — QA בלבד

- בלי cookies ובחלון פרטי: `/`, `/create`, `/checkout`, דמו ומשחק דורשים כניסה; API מחזיר 401 ללא DB/רנדר.
- סיסמה שגויה לא יוצרת cookie. סיסמה נכונה מאפשרת את האתר; היא לא נראית ב־URL/HTML/קונסולה.
- סיסמה חסרה/קצרה: סגור. ייצור מקומי ופרודקשן אינם ננעלים בטעות.
- לנסות POST ישיר עם `x-middleware-subrequest`, cookie מזויף ו־Vercel bypass מזויף. אין גישה.
- אין מעבר לכתובת חיצונית דרך `next`. כניסה מחדש אחרי החלפת סיסמה; תפוגת עוגייה 24 שעות.
- HE/EN ו־320/390px: שדה נגיש, כפתור ברור, טקסט לא נחתך.
- `qa.findmeworlds.com` וה־alias הישן של QA מכוסים. לפחות כתובת היסטורית אחת דורשת Vercel Authentication.
- cron טבעי חוזר 200; לא להריץ ידנית רנדר או משחק בתשלום כדי לבדוק את השער.
- `findmeworlds.com` נשאר 503 / DEPLOYMENT_PAUSED.
- בדיקות אוטומטיות: `src/lib/__tests__/qa-access*.test.ts`, בנוסף ל־`npm run check` המלא.

תוצאות הפריסה והבדיקה החיה נרשמות בקובץ הראיות הנלווה; מסמך זה מתאר את חוזה הקוד ולא טוען שנוצר משחק אישי חדש ונמסר למייל.
