# Board paint engine and passport finale — QA handoff

## Requested scope

Integrate the user's approved second Bar dragon-stool style direction into the actual generation engine, then publish the engine and bound-passport completion UI to the dedicated QA project. This is not permission to overwrite every delivered personalized image or activate a different paid catalog.

## Engine change

- New recipe: `local-patch-prompt/v12-board-paint-identity`, selected by the production hide runner when it creates a new variant row.
- Image 2 determines identity geometry, hair pattern and age. The original board people determine surface painting, warm/cool facial planes, brush-detail scale, material response and local light. Neighbour identities must not transfer.
- Explicit whole-body scale, physically plausible floor/prop contact, natural activity/gaze, preserved edit boundaries and discovery objects.
- Repair instructions preserve the same separation; repairing likeness must not reintroduce smooth portrait rendering.
- No noise filter, global image treatment, quality-gate weakening, changed attempt allowance or budget increase.
- New prompt/version is part of the existing paid-operation fingerprint. Existing variant rows retain their historical recipe; replay cannot reinterpret a prior purchase under the new recipe. Already generated/approved rows return without another purchase.
- Historical direct renderer callers retain their existing default unless they explicitly select `paintRecipe: "board-paint-v1"`. This includes frozen offline rendering scripts.

The approved image is a visual reference, not evidence that every image generated by this revised prompt will pass visual acceptance. A fresh real-provider sample and contextual review remain necessary before mass rendering.

## Tests and release evidence

Targeted tests cover new recipe dispatch/persistence on real disposable SQLite, historical row continuation, retained-purchase refusal on a changed fingerprint, replay without a second provider call, age/reference invariants and canonical identity reuse. The reuse integration assertion was updated from an old uppercase heading to explicit identity and paint authority clauses; its image/reference and billing assertions remain intact.

The first full run suffered a roughly ten-hour wall-clock discontinuity and four timeout failures. It also exposed the old heading assertion and its cascading mock-call failures. Those results are not counted as a passing gate; the subsequent complete gate and release receipt are reported separately.
