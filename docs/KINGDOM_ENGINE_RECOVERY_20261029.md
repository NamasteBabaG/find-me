# Kingdom engine recovery, 2026-10-29

Real QA exposed two independent problems: a complete MEDIUM answer could fail
strict subject parsing when it repeated the question's two binding hashes inside
the subject document, and a provider could paint a complete body outside the
unchanged returned window. A crop could also hide the source head belonging to a
body that continued into the editable area. A good-looking RAW crop is therefore
insufficient evidence about the player image.

## Exact paid-answer reconciliation

`quality-subject-envelope/v2-exact-nested-echo` accepts only a complete, matching
pair of photo/plan hashes inside the subject, in addition to the previously
qualified outer echo. Historical v1 reading remains available. The v2 reader
removes only those redundant labels; all semantic fields still pass through the
original strict quality, subject, continuity, native crown and doubt gates.

The existing fenced QA reconciliation can wake an exhausted original paid world
for this free re-reading. All roles must prove the same retained settled response,
image, geometry, identity and rebuilt question. Previous decisions stay in review
history. No provider request, attempt, source pixel or ledger entry is rewritten.
Unknown charges remain fully reserved. Foreign/partial hashes do not qualify.

## Prospective placement guide

`local-patch-placement-guide/v1` is persisted before an unstarted image purchase
in a from-birth MEDIUM world. Its receipt binds the attempt, source, original
geometry and original review authority. New ordinary paintings and eligible new
guided thirds receive a local whole-target frame plus a separate original-source
context panel showing people continuing outside the crop. The source crop,
authored child envelope, returned window and composition contracts remain fixed.
Existing special body/native-context strategies retain their own recipes.

An already reserved purchase or a live historical PENDING claim without this pin
keeps its original recipe and fingerprint. An unreserved PENDING attempt older
than the existing six-minute takeover lease may adopt the prospective guide
without consuming another attempt. An interrupted guided purchase resumes
the persisted recipe and retained response. No additional attempt or money is
authorized by this software change. Images still need independent final MEDIUM
approval of the actual returned player pixels before all-27 publication.

## Complete CI scheduling

The unpartitioned Detective integration file exceeded the core job's 100-minute
limit while still running complete-world scenarios. Its assertions and per-test
limits remain unchanged. CI now collects all expanded test names, sorts them and
assigns each exactly once across four isolated runners using an exact escaped
name pattern. Each runner checks that Vitest collects precisely its assigned
cases before executing them. New cases join the partition automatically; empty,
duplicate or foreign inventories fail closed. Core checks, the lean world file,
all four Detective partitions, validators, build and private-asset audits must
all pass in one run on the same commit before the existing QA release guard can
authorize deployment.

The live completion action also exposed a transaction-storage scope gap: its
fenced recheck kept the outer `DbStorage` instance after switching the database
client to the transaction. A limited connection pool could therefore wait on
itself, and the source-byte read was outside the atomic snapshot. The completion
transaction now binds both database and DB storage to the same transaction
client, as the existing capacity-recovery paths do. A synthetic single-connection
guard reproduces the failure on the previous implementation and qualifies both
Kingdom families. Refused actions record only a fixed domain reason or a Prisma
error code, never arbitrary exception text or private authorization evidence.
